# Robot Navigation Workbench

《智能机器人技术》实验一「机器人避障」的二维仿真工作台。设定起点和终点，让小车在静态与动态障碍物之间自主行驶，再用相同场景比较算法的安全性和到达表现。

- [项目规格](docs/robot_navigation_workbench_spec.md)说明课程要求、开发阶段与验收标准。
- [架构与目录](docs/ARCHITECTURE.md)说明仿真、算法、实验、API 和前端的职责。
- [项目术语](GLOSSARY.md)说明场景、实验运行和避障成功的含义。

## 架构

后端是仿真状态的唯一真相来源：`backend/app/simulation/` 内的固定时间步引擎（dt = 0.05 s，unicycle 运动学，子步进碰撞检测，到达 / 超时 / 被困判定）被实时会话和无界面批量实验共用，`backend/app/algorithms/` 中的三种算法（A*、APF、A*+APF 混合）只读取当前观测、输出运动指令，`backend/app/experiments/` 负责批量运行、指标汇总与 CSV/JSON 导出，`backend/app/api/` 用 FastAPI 把这些能力暴露成 REST + WebSocket。前端只渲染快照并发送命令：React 19 + Konva 画布绘制地图与轨迹，Recharts 绘制实验对比图，机器人运动完全由后端快照驱动，没有任何动画伪造。

## 运行

需要 Python 3.11+ 与 `uv`、Node.js 24 LTS 与 npm。在两个终端分别运行：

> 国内网络下 `uv sync` 可能长时间无响应，可改用镜像源：
> `uv sync --default-index https://pypi.tuna.tsinghua.edu.cn/simple`。

```sh
cd backend
uv sync
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```sh
cd frontend
npm ci
npm run dev
```

Windows 与 macOS 均可运行（命令不含平台特有语法）。浏览器打开 `http://localhost:5173`；开发服务器已把 `/api`（REST + WebSocket）代理到 `127.0.0.1:8000`。后端地址不在默认端口时，用 `VITE_API_BASE_URL` 指定。

测试与构建：

```sh
cd backend && uv run pytest -q     # 44 个测试
cd frontend && npm run build       # tsc --noEmit + vite build
```

## 内置场景

| 场景 | 内容 | 考察点 |
| --- | --- | --- |
| 静态基础 `static-basic` | 20×12 m，带缺口的中央墙带 + 7 枚静态圆形障碍（全部压在必经通道上） | 全局绕行，连续绕桩并穿过缺口 |
| S形绕桩 `static-slalom` | 22×10 m，三道上下交错的墙体门迫使路线呈 S 形，每个直段的桩位正对路线 | 连续大幅变向，绕开正对必经之路的桩 |
| 动态交叉 `dynamic-crossing` | 24×12 m，一根 1×2 m 矩形立柱上下往返横穿走廊（半周期 5 s） | 直线通路被周期切断，重规划 / 择机通过，不做重规划的直线行驶会相撞 |
| 双重动态交叉 `dynamic-double-crossing` | 24×12 m，两根 1×2 m 立柱反相上下往返横穿（半周期 7.5 s，扫掠速度恰为机器人上限 1.2 m/s），中间另有 2 枚静态圆障碍 | 一段通路打开时另一段可能正被切断，多重择时通过 |
| 混合通道 `mixed-corridor` | 20×10 m，两道墙体门形成狭窄通道，通道内一枚动态圆障碍左右巡逻（半周期 2.5 s）+ 一枚静态圆障碍 | 静动态混合，有限空隙内的实时避让 |
| 双巡逻拦截 `dynamic-patrol-line` | 20×10 m，两枚动态圆障碍贴着直线上方反相巡逻（半周期 2.5 s）+ 2 枚静态圆障碍封锁进出口车道 | 对头遭遇下的择机穿隙与绕桩 |

动态障碍物的运动是仿真时间的纯函数：同一种子下每个时刻的位姿完全一致，这是批量实验可复现的基础。

## 算法

三种算法共用同一个引擎：相同的机器人模型（半径 0.25 m、默认 v_max 1.2 m/s）、相同的碰撞与目标判定、相同的观测（环境中所有障碍物的当前位姿，无未来信息）。可在顶部设置安全边距与速度上限覆盖默认值，改动同时作用于算法与机器人。

**A\* 全局规划**：把场地栅格化（0.1 m/格），按机器人半径加安全边距膨胀障碍物，8 连通搜索（禁止切角），再用视线剪枝简化路径，交给通用航点跟随器执行。行驶中每隔 1 s 重新规划一次，另外当下一段路径与任何障碍物当前位置的间距小于膨胀半径时立即触发重规划；重规划只看当前障碍位姿，失败时保留旧路径并记录原因。优点是全局路径质量稳定、有明确的成功与失败依据；缺点是依赖栅格分辨率——路径可能贴着膨胀边界，在密集动态场景中会频繁重规划，个别时刻可能短时无路可走（此时继续沿旧路径行驶，可能碰撞）。重规划次数与规划耗时单独计入指标。

**人工势场法（APF）**：不规划路径，每步直接由合成力转向——目标引力（圆锥势阱）+ 每个障碍物表面的斥力（反比核，带距离下限和单源上限，防止力爆炸）+ 沿障碍物表面滑动的切向涡旋分量（滑动方向按接触时确定并锁存，避免符号抖动），力映射为 `(v, ω)` 时受到与 A* 相同的速度与角速度限制。优点是零规划耗时、对动态障碍物反应即时；致命弱点是局部极小值：合力为零或与目标方向对冲的凹形口袋会让它原地停滞。本项目不"救活"它——引擎在 6 s 无目标进展时判定 STUCK，控制器在 3 s 无进展时提前给出"被困"提示信息（仅提示，不改判结果），超时与碰撞照常如实记录。

**A\*+APF 混合**：A* 提供全局航点，航点之间不用航点跟随器而用 APF 力场转向。重规划有三类触发条件（任一满足即触发，会话层做节流）：① 局部阻塞——朝向**中间航点**的合力投影连续 20 步（1 s）低于自由空间引力的 25%，说明局部场"呛住"了前进；② 下一段路径接近任何障碍物当前位置（与 A* 基线共用同一条接近规则）；③ 每 1 s 的周期性检查。设计动机是把 A* 的全局性与 APF 的实时局部避障结合：动态障碍物只是暂时挡路时靠力场绕过并等待，长期改变地形时由全局层重新规划。局限：接近终点时局部阻塞不触发重规划（此时阻塞是诚实的 APF 行为，重规划救不了被困的力场），因此继承 APF 的局部极小弱点；重规划本身也可能失败（保留旧路径）。

## 批量实验与结果导出

底部「批量实验对比」面板选择场景、勾选算法（默认 A* 与 APF）、设置种子数后即可运行；也可以用 API 直接复现：

```sh
curl -X POST http://127.0.0.1:8000/api/experiments/batch \
  -H "Content-Type: application/json" \
  -d '{"scenario_id": "dynamic-crossing", "algorithms": ["astar", "apf", "hybrid"], "seeds": [1, 2, 3, 4, 5]}'
```

每次批量运行把每个（算法 × 种子）组合无界面地完整跑一遍（复用与实时会话完全相同的引擎），返回逐次运行指标与按算法汇总的成功率、平均用时、平均行驶距离、碰撞次数、重规划次数和逐结果计数。结果同时导出到 `backend/exports/{scenario_id}_{时间戳}/`：

- `runs.csv` — 每次运行一行的原始指标；
- `summary.csv` — 每个算法一行的汇总（含各结果计数列）；
- `results.json` — 两级数据 + 元数据（场景、算法、种子、生成时间、代码版本）。

所有失败（`collided` / `timeout` / `stuck` / `planning_failed`）都保留在汇总里，成功率按全部运行次数计算，不会把失败剔除或折算成成功。约束：每次最多 4 个算法、20 个种子。除 `planning_ms`（墙钟计时）外，同一种子的所有运行字段逐位可复现。

## 界面说明

- **顶部控制栏**：场景选择、算法 A/B（并排对跑时）、随机种子、安全边距、速度上限、新建会话，以及开始 / 暂停 / 单步 / 重置。并排对跑时命令同时发给两个会话，重置会按当前参数重建两个会话（初始条件还原、场景编辑丢弃）。
- **并排对跑**（课堂主视图）：同一场景、同一种子下两个算法同步运行，两张地图共用比例尺、图层开关和图例，各自带状态徽章与指标条，A/B 算法对比时保证画面可比。
- **单车详情**：大地图 + 右侧「状态 / 事件 / 场景编辑」面板。事件面板滚动记录到达、碰撞、超时、被困、重规划与后端消息；场景编辑支持拖拽障碍物、起点、终点，添加（静态圆形 / 矩形）与删除障碍物，点「应用场景修改」经 `PUT /api/sessions/{id}/scene` 提交——仅暂停 / 待机时可用（运行中提交会得到 409 `scene_locked`），修改后无法规划出路径会被 400 `invalid_scene` 拒绝并保留原场景。拖拽动态障碍物会平移其运动路径。
- **图层**：图例即开关——膨胀区、A* 栅格与搜索节点、规划路径、实际轨迹、机器人朝向、动态障碍物速度箭头、APF 力箭头（默认关闭，可在单车详情中打开观察力场方向）。开关状态存入 localStorage，刷新后保留。
- **批量实验对比**：底部面板，Recharts 柱状图展示成功率、平均用时、平均行驶距离、平均碰撞次数与逐结果失败计数，附导出目录提示。

## 已知限制

- 算法观测是 **full-state observation**（理想全局感知）：能看到所有障碍物的当前位姿与速度，没有探测半径、遮挡或传感器噪声。
- 场景编辑只支持静态障碍物的增删改；动态障碍物可以整体拖动，但不能新建或修改运动参数（幅度、周期等），也不能编辑场地尺寸。
- 批量实验只在六个预设场景上运行，每次最多 4 个算法 × 20 个种子。
- 实时模式下若机器负载过高，单次最多补 100 步（5 s 仿真时间），极端卡顿时会慢于实时；批量实验不受影响。
- `planning_ms` 是墙钟计时，不在可复现性比较之列。
- 会话与实验结果保存在内存 / 本地 `exports/` 目录，重启后端后旧会话丢失。
- 未实现规格中的可选项：传感器受限观测、实验日志重放、栅格分辨率调节。
- 前端产物约 1.2 MB（Recharts + Konva 占大头），首次加载稍慢；内网课堂环境可接受。
